            Windows blocked an app or build?
            
Your approval matters, but it does not override Windows security. Capsule consent approves a specific Toolbox action; Windows UAC permits elevation; Application Control separately decides which executables may run. Approving one does not approve the others.

            
Review the Windows block

            
Record the blocked file, publisher, time and exact error. Error 4551 means an Application Control policy blocked execution; it is not proof that the file is malicious or safe.

            
Open Windows Security and review Protection history if an entry is available. For Application Control details, open Event Viewer, then Applications and Services Logs > Microsoft > Windows > CodeIntegrity > Operational. Event 3077 can identify the blocked file and policy ID. Viewing some details may require administrator access.

            
Use the supported approval process

            
On a managed device, give your administrator the event details and obtain approval through the organization's signing or Application Control policy process. On a personal device, review App & browser control in Windows Security to identify the protection involved; available options depend on the policy and Windows version. Some protections do not offer a per-file exception.

            
For a developer build, use approved tooling and signed artifacts where required, or an approved Windows build environment. Running as administrator alone does not override Application Control.

            
Capsule cannot grant a Windows security exception. Do not disable protection, rename or relocate blocked executables to evade enforcement, or run an unverified replacement. This guidance does not read logs, change policies, install certificates or execute commands.
